# 03. Выгрузка/загрузка конфигурации 1С и её автоматизация

> Исследование: способы выгрузки/загрузки конфигурации 1С:Предприятие 8, инструменты автоматизации и их сравнение.
> Контекст: подключение MCP к 1С на Windows + VS Code + агент + 1С:Предприятие.

## 1. Форматы хранения конфигурации

Конфигурация 1С существует в нескольких представлениях:

| Представление | Формат | Назначение |
|---|---|---|
| Информационная база (ИБ) | база (файловая `1Cv8.1CD` или серверная SQL) | рабочая/разработка |
| Файл поставки конфигурации | `.cf` (расширение — `.cfe`) | бинарный контейнер, дистрибуция |
| Файл выгрузки ИБ | `.dt` | полный бэкап базы (конфигурация + данные) |
| Исходники (выгрузка в файлы) | XML-иерархия (`.xml`, `.bsl`, `.html`, `.bin`, `.mdo`, `.form` и др.) | версионирование, diff, CI/CD |
| Проект EDT | набор файлов Eclipse-проекта (`.mdo`, `.form`, `.bsl`) | разработка в EDT, git |

Ключевой факт для MCP-интеграции: **только XML-выгрузка (иерархическая) и формат EDT пригодны для построчного diff и работы с git**. Файл `.cf` — бинарный контейнер (формат "контейнер" с deflate-сжатием вложений), его коммит в git превращается в непрозрачный блоб на сотни мегабайт.

## 2. Штатные средства конфигуратора (интерактивно)

### 2.1. Выгрузка/загрузка в файлы (XML)
Меню **Конфигурация → Выгрузить конфигурацию в файлы…** / **Загрузить конфигурацию из файлов…** (в новых версиях — «Сохранить конфигурацию в файлы»).

- Выгружает **полный** состав: модули, макеты, права доступа, справочную информацию, картинки — в каталог в виде набора файлов.
- Тип файла соответствует содержимому: структура объекта (справочник, документ) → `.xml`, модуль объекта → текстовый `.bsl`, макеты/картинки → `.bin`.
- Выгрузка выполняется в **иерархический формат** (избавляет от сверхдлинных имён файлов).
- Поддерживается **инкрементальная** выгрузка/загрузка (только изменённые файлы).
- Опции диалога: выгружать на сервере (для клиент-серверных баз, с фоновыми заданиями), не выгружать ссылки на несуществующие объекты, выгрузка в XML-файлы или в архив.
- Для расширений: переключение на расширение и отдельная выгрузка (`.cfe`), одной командой все расширения штатно не выгружаются.

### 2.2. Выгрузка/загрузка `.cf` / `.dt`
- **Конфигурация → Сохранить конфигурацию в файл…** → `.cf` (поставка конфигурации).
- **Конфигурация → Загрузить конфигурацию из файла…** → полная замена текущей конфигурации на загружаемую (без сравнения/объединения).
- **Администрирование → Выгрузить информационную базу… / Загрузить информационную базу…** → `.dt` (полный снимок базы).

## 3. Командная строка 1cv8 (пакетный режим конфигуратора)

Пакетный режим (`DESIGNER`) — основной способ автоматизации без участия человека. Ключевые параметры (из руководства администратора, приложение 7):

| Команда | Назначение |
|---|---|
| `/DumpCfg <файл.cf>` | выгрузить конфигурацию в `.cf` |
| `/LoadCfg <файл.cf>` `[-Extension имя]` | загрузить конфигурацию/расширение из `.cf`/`.cfe` |
| `/DumpIB <файл.dt>` | выгрузить информационную базу (`.dt`) |
| `/RestoreIB <файл.dt>` | загрузить ИБ из `.dt` |
| `/DumpConfigToFiles <каталог>` `[-Extension имя] [-AllExtensions] [-Format иерархический]` | выгрузить конфигурацию в XML-файлы (полная выгрузка) |
| `/LoadConfigFromFiles <каталог>` `[-Extension] [-AllExtensions] -files/-listFile -Format -partial` | загрузить конфигурацию из XML-файлов (в т.ч. частичная загрузка) |
| `/DumpConfigFiles <каталог>` `[-Module -Template -Help -AllWritable -Picture -Right]` | выгрузить отдельные свойства объектов (модули, макеты, права) |
| `/LoadConfigFiles <каталог>` | загрузить отдельные свойства объектов |
| `/UpdateDBCfg` | обновить конфигурацию БД (после `/LoadCfg`, `/LoadConfigFromFiles` и др.) |
| `/CheckModules` | синтаксический контроль модулей |

Типовой сценарий сборки из исходников в CI (пустая файловая база):

```
"C:\Program Files\1cv8\8.3.24.xxx\bin\1cv8.exe" CREATEINFOBASE "File=D:\build\ib"
"C:\Program Files\1cv8\8.3.24.xxx\bin\1cv8.exe" DESIGNER /F "D:\build\ib" \
    /LoadConfigFromFiles "D:\repo\src\cf" /UpdateDBCfg -Dynamic- /Out "D:\logs\build.log"
"C:\Program Files\1cv8\8.3.24.xxx\bin\1cv8.exe" DESIGNER /F "D:\build\ib" \
    /CheckModules -ThinClient -Server -ExternalConnection /Out "D:\logs\check.log"
"C:\Program Files\1cv8\8.3.24.xxx\bin\1cv8.exe" DESIGNER /F "D:\build\ib" \
    /DumpCfg "D:\build\artifacts\1cv8.cf" /Out "D:\logs\dump.log"
```

Дополнительно:
- `/DisableStartupDialogs` — подавление стартовых диалогов (обязательно в CI).
- `/Out <файл>` — лог выполнения.
- Код возврата: 0 — успех, 1 — ошибка (101 — ошибки в данных).
- Ключ `-update` у `/DumpConfigToFiles` даёт **инкрементальную** выгрузку (по замеру на УТ 11.5/8.3.24: полная 25–45 мин, инкрементальная 1–3 мин).
- **Режим агента конфигуратора** — альтернатива пакетному режиму, доступ к операциям конфигуратора по HTTP/REST (важно для MCP-серверов).

### Параметры запуска и подключение
- `/F <путь>` — файловая база; `/S <server>\<base>` — серверная; `/IBConnectionString "..."` — строка соединения; `/N <пользователь>` `/P <пароль>` — аутентификация.

## 4. 1C:EDT (1C:Enterprise Development Tools)

EDT — среда разработки на базе Eclipse. Конфигурация в EDT — это **проект** (набор файлов/каталогов на диске), физически это исходники в формате EDT (`.mdo`, `.form`, `.bsl` и др.).

- Проект хранится как текстовые файлы → напрямую совместим с git (встроенный EGit: ветки, merge, code review).
- **Импорт** существующей конфигурации из ИБ/`.cf`/XML-выгрузки в проект EDT; **экспорт** проекта обратно в формат конфигуратора (`.cf` или XML-выгрузка) — выполняется через CLI (`ring` до EDT 2024.01, далее `1cedtcli`) или через конфигуратор.
- Сам EDT **не умеет** собирать `.cf` и обновлять базу — для сборки всё равно вызывается конфигуратор в пакетном режиме (`/LoadConfigFromFiles`).
- Программный интерфейс: API `IRuntimeExecutionCommandOptions` c константами `DUMP_CONFIG_TO_FILES` (DumpConfigToFiles), `LOAD_CONFIGURATION_FROM_XML` (LoadConfigFromFiles), `LOAD_CONFIGURATION_FROM_CF` (LoadCfg), `DUMP_CONFIG_TO_XML` и др. — т.е. те же ключи конфигуратора, обёрнутые в Eclipse runtime.
- Есть сторонний MCP-сервер `DitriXNew/EDT-MCP` (MCP для 1C:EDT), работающий с проектом и git.

## 5. gitsync (синхронизация хранилища 1С ↔ git)

**gitsync** (библиотека + консольное приложение OneScript, репозиторий `oscript-library/gitsync`, ранее — `silverbulleters/gitsync`; лицензия MPL 2.0) — превращает историю **хранилища конфигурации** 1С в историю git-репозитория.

- Каждая версия (закладка) хранилища → отдельный коммит git с автором, датой и комментарием.
- Требует чтения файлов хранилища напрямую (не поддерживает tcp/http-доступ), плюс утилиту `ring` от 1С для работы с форматом хранилища (для 1С > 8.3.11).
- Установка: `opm install gitsync`. Запуск: `gitsync sync --v8version 8.3.24.1548 "tcp://srv/repo" "D:\repo"`.
- Плагины: `increment` (инкрементальная выгрузка), `sync-remote`, `unpackForm` (распаковка обычных форм через v8unpack), `smart-tags`, `check-authors`, `check-comments` и др.
- Ограничения: полная выгрузка тяжёлых конфигураций (ERP) — от 15 мин до 1 ч на версию; временные каталоги забивают диск (нужно чистить).
- Альтернатива — официальный **1С:ГитКонвертер** (`1C-Company/GitConverter`): односторонняя синхронизация хранилища в git, конвертирует историю в формат EDT; рекомендуется при хранилище > 300 Мб / > 1000 версий с Git LFS.

## 6. v8unpack / v83unpack (распаковка `.cf`/`.epf`/`.erf` без платформы)

Семейство утилит для сборки/разборки бинарных файлов 1С **без установки платформы**.

- **Оригинальный v8Unpack** — Денис Демидов (assembla); **e8tools/v8unpack** — gcc-порт (C/C++, кроссплатформенный), форк оригинала. Работает на низком уровне: распаковка/запаковка контейнера `.cf`, inflate/deflate, `-U[NPACK]` / `-B[UILD]` / `-P[ARSE]`.
- **saby-integration/v8unpack** (Python, `pip install v8unpack`, автор — Разговоров М.А., на основе Python-реализации Infactum/onec_dtools) — "человекочитаемая" распаковка: 4 этапа (стандартный v8unpack → JSON → декодирование заголовков → организация структуры). Даёт человекочитаемые исходники (код форм в отдельных файлах, JSON-описания), пригодные для git.
- Команды: `v8unpack.exe -E d:/sample.cf d:/unpack` (распаковать), `v8unpack.exe -B d:/unpack d:/repacked.cf` (собрать), ключ `--descent` для расширений (наследование версий).
- Применение: хранение внешних обработок/расширений в git в читаемом виде, сборка расширений под разные конфигурации из одних исходников.
- ВАЖНО: результат v8unpack **не взаимозаменяем** с выгрузкой конфигуратора (это не штатный формат `ВыгрузитьКонфигурациюВФайлы`) — это сторонний разбор бинарника, для обратной загрузки в конфигуратор используется штатный `/LoadConfigFromFiles`.

## 7. OneScript (oscript) и его библиотеки

**OneScript** (`EvilBeaver/OneScript`, сайт oscript.io) — кроссплатформенная VM, исполняющая скрипты на языке 1С:Предприятие **без установки платформы** (аналог по концепции Python/Node для 1С-ника).

- Пакетный менеджер **opm** (`oscript-library/opm`), экосистема `oscript-library`.
- Актуальная ветка v2.x — на .NET 8.
- Ключевые библиотеки для автоматизации выгрузки/сборки:
  - **gitsync** (см. §5).
  - **vanessa-runner** — запуск сценариев сборки/тестов.
  - **1commands** / библиотеки управления конфигуратором — обёртки над командной строкой 1cv8 (создание файловой базы, `ЗагрузитьКонфигурациюИзФайла`, `/DumpConfigToFiles`, `/UpdateDBCfg`).
  - **precommit4onec** — обработка исходников при помещении в git.
  - **yard** (arkuznetsov) — загрузка релизов с releases.1c.ru, сборка CF из CFU, конвертация в EDT, выгрузка версий в git.
- Позволяет писать кроссплатформенные скрипты CI/CD на привычном 1С-никам языке (вместо bat/sh).

## 8. Автоматизация через COM-соединение (V83.COMConnector)

COM-коннектор `V83.COMConnector` (`comcntr.dll` в каталоге платформы, ProgID `V83.COMConnector`) — программный интерфейс к информационной базе. Только Windows.

- Даёт: подключение к базе (`Connect("File=...;Usr=...;Pwd=...")`), чтение **метаданных** (`Метаданные`), выполнение запросов, работу с данными, запуск внешней обработки/кода (через отдельный executor — напрямую `Выполнить`/`Вычислить` внешнее соединение не поддерживает).
- **НЕ даёт** штатных операций конфигуратора (`ВыгрузитьКонфигурациюВФайлы`, `/DumpConfigToFiles`): это функции конфигуратора, а не внешнего соединения. COM-коннектор позволяет программно читать структуру метаданных и строить собственное представление, но полную XML-выгрузку делает конфигуратор в пакетном/агентном режиме.
- Использование из Python — через `win32com`/`pywin32` (напр. библиотека `oneCInteraction`), из .NET — через `Activator.CreateInstance(Type.GetTypeFromProgID("V83.COMConnector"))`.
- Существуют готовые MCP-серверы поверх COM: `mcp-1c-com`, `1c-via-com-mcp-server` (запросы, листинг метаданных, выполнение скрипта) — релевантный прототип для подключения MCP к 1С без изменений в базе.
- Для серверного кластера кросс-платформенно вместо COM используется `ras`/`rac`; COM — только Windows (актуально для нашего сценария).

## 9. Сравнительная таблица

| Инструмент / метод | Автоматизируемость | Результат (формат) | Сложность | Зрелость |
|---|---|---|---|---|
| Конфигуратор, интерактивно (`Выгрузить/ЗагрузитьКонфигурациюВФайлы`, `.cf`) | Низкая (ручные действия, GUI) | XML-иерархия / `.cf` / `.dt` | Низкая | Официальный, максимальная (эталон) |
| Командная строка 1cv8 (`/DumpConfigToFiles`, `/LoadConfigFromFiles`, `/DumpIB`, `/DumpCfg`, `/LoadCfg`) | **Высокая** (пакетный/агентный режим, CI) | XML-иерархия, `.cf`, `.dt` | Средняя (синтаксис ключей) | Официальный, максимальная |
| Режим агента конфигуратора | Высокая (HTTP/REST) | XML, `.cf` | Средняя | Официальный |
| EDT (проект) + `ring`/`1cedtcli` | Высокая (CLI, git встроен) | проект EDT / экспорт в `.cf`/XML | Высокая (Eclipse, ресурсоёмко) | Официальный, развивается (замена конфигуратора) |
| 1С:ГитКонвертер (`1C-Company/GitConverter`) | Высокая (регламентные задания) | git-репозиторий (формат EDT) | Средняя | Официальный, поддерживается |
| gitsync (oscript-library) | Высокая (CLI, расписание) | git-репозиторий (XML-выгрузка конфигуратора) | Средняя | Сообщество, зрелый (335+ звёзд, с 2016) |
| v8unpack (e8tools, C++) | Средняя (CLI) | текстовые файлы/контейнер | Низкая | Сообщество (низкоуровневый) |
| v8unpack (saby-integration, Python) | Высокая (CLI/Python API) | человекочитаемые JSON/исходники | Средняя | Сообщество, активный |
| OneScript (oscript) + библиотеки | Высокая (скрипты CI/CD) | оркестрация (обёртки над 1cv8/git) | Средняя | Сообщество, зрелый (v2.x, .NET 8) |
| COM-соединение (V83.COMConnector) | Высокая (код) | доступ к метаданным/данным (не полная выгрузка) | Средняя | Официальный, Windows-only |

**Вывод для MCP-интеграции:** базовая пара для автоматизации выгрузки/загрузки — **командная строка 1cv8** (`/DumpConfigToFiles` + `/LoadConfigFromFiles`) или **режим агента конфигуратора** (HTTP). Для git-истории хранилища — **gitsync**/ГитКонвертер. Для разбора `.cf` без платформы — **v8unpack**. Для чтения метаданных/данных из работающей базы — **COM-коннектор**.

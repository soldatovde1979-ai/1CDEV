# План: рабочее место для AI-ассистированной разработки 1С/BSL (VS Code + Zoo Code + mcp-1c)

**Описание:** Настройка связки «выгруженная конфигурация в VS Code + BSL Language Server + MCP-доступ агента к живым метаданным базы», без Docker, без платных компонентов (кроме самой модели DeepSeek). Аналог Напарника в EDT, собранный из открытых инструментов. Часть шагов выполняет Zoo Code (агент) командами и правкой файлов, часть — ты сам через интерфейс (Конфигуратор, браузер, почта).

**Инструменты:** 1С:Конфигуратор, VS Code, Zoo Code, BSL Language Server, mcp-1c (бинарник), Java (для BSL LS), Apache/IIS (публикация HTTP-сервиса 1С).

**Время:** 1.5–2.5 часа при первом прохождении, с учётом переноса файлов между контурами.

**Исполнители:** [Р] — ты, клики в интерфейсе (Конфигуратор, VS Code, почта) на ПК внутреннего контура. [В] — ты, во внешнем контуре/дома (там, где нужен открытый интернет). [А] — Zoo Code, команды и правка файлов во внутреннем контуре.

**Шаги:** Проверка версии платформы > Выгрузка конфигурации > Открытие в VS Code > JDK 21 и BSL LS > Скачивание mcp-1c > Перенос во внутренний контур > Автоустановка расширения > Публикация HTTP-сервиса > Проверка сервиса > Подключение MCP к Zoo Code > Проверка в диалоге > Перенос правил разработки 1С > mcp-bsl-lsp-bridge и rlm-tools-bsl

## Этап 1. Подготовка и выгрузка конфигурации

### 1.1 Проверка версии платформы 1С [Р]

Нужна для двух вещей дальше: минимальная версия для `mcp-1c` — 8.3.10, а для готового `.cfe`-файла расширения — 8.3.14. Версия платформы обычно видна в заголовке окна Конфигуратора или в «Справка > О программе».

Открой Конфигуратор > «?» (Справка) > «О программе». Запиши версию — понадобится агенту на шаге 4.1.

> **Инфо:** Платформа — это сама программа «1С:Предприятие» (движок), отдельно от конфигурации (прикладного решения вроде ERP или ЗУП). Версия платформы и версия конфигурации — разные числа, не перепутай при поиске в заголовке.

### 1.2 Выгрузка конфигурации в файлы [Р]

Это создаёт XML-представление всей конфигурации на диске — то, что дальше открывается в VS Code вместо (или вместе с) визуальным Конфигуратором. Пункт меню, не команда — агент выполнить не может.

В Конфигураторе: `Конфигурация > Выгрузить конфигурацию в файлы...`, укажи пустую папку, например `C:\Projects\1C_ERP\src`. Процесс может занять от нескольких минут до десятков минут на крупных конфигурациях (ERP, УХ) — по объёму метаданных. Успех — папка заполнилась XML-файлами и подпапками по видам объектов (`Documents`, `Catalogs`, `CommonModules` и т.д.).

> **Инфо:** Формат этой выгрузки — плоские XML-файлы, тот же принцип, что использует `git`-хранение конфигураций 1С (EDT тоже выгружает в похожий, но не идентичный формат — они не взаимозаменяемы напрямую).

## Этап 2. Просмотр и редактирование в VS Code

### 2.1 Открытие выгруженной папки в VS Code [Р]

Проверяем, что структура читается как обычный текстовый проект — это база для дальнейшей работы агента и твоей собственной. Открытие рабочей папки — твоё действие в интерфейсе VS Code, даже если дальше в этой же папке работает агент.

`Файл > Открыть папку` > указать `C:\Projects\1C_ERP\src`. В дереве слева должна появиться структура метаданных с XML- и BSL-файлами. Открой любой `.bsl`-файл модуля — должен показаться обычный текст на русском (процедуры, функции), без подсветки синтаксиса на этом шаге (она появится после установки BSL LS).

### 2.2 Проверка установленного JDK [А]

По твоему проекту уже в процессе установка JDK 21 под BSL Language Server (он требует Java 21, а установлен был 17). Дай агенту задачу: проверить текущее состояние перед тем как продолжить — если JDK 21 уже стоит, шаг 2.3 можно пропустить.

```powershell
& "C:\Java\jdk-21\bin\java.exe" -version
```

Если команда выводит `openjdk version "21...` — Java 21 уже на месте, переходи к 2.4. Если путь не найден — продолжай к 2.3.

### 2.3 Установка JDK 21 без изменения системного PATH [В]>[А]

Устанавливаем в изолированную папку, чтобы не конфликтовать с уже стоящим JDK 17 и не трогать системные переменные (для чего обычно не нужны права администратора при установке в пользовательскую директорию).

> **Инфо:** Eclipse Temurin — открытая сборка OpenJDK, используемая по умолчанию во многих корпоративных средах как замена Oracle JDK (без лицензионных ограничений последнего).

[В] Скачай `.zip`-дистрибутив (не `.msi`-инсталлятор — он может требовать прав администратора) Eclipse Temurin JDK 21 для Windows x64 с `adoptium.net` — домен, скорее всего, недоступен во внутреннем контуре, скачивание во внешнем контуре/дома, перенос — Яндекс Почтой (как в шаге 3.2).

[А] Дай агенту задачу распаковать архив в `C:\Java\jdk-21` после того, как ты положишь `.zip` в доступную ему папку.

### 2.4 Настройка BSL Language Server в VS Code [А]

Прописываем путь к конкретной версии Java явно в конфиге MCP/расширения, а не полагаемся на системный `PATH`, где может остаться JDK 17. Правка конфигурационного файла — задача агенту.

Попроси агента открыть `.roo/mcp.json` в корне проекта (`C:\Projects\1C_ERP`) и добавить (или проверить) путь к `bsl-language-server-1.0.7.jar` с указанием полного пути к `java.exe` из шага 2.2/2.3 — конкретный формат записи зависит от того, как расширение VS Code для BSL ожидает конфигурацию (уточняется агентом по документации самого расширения на месте, если запись отличается от предполагаемой).

> Этот шаг у тебя уже частично сделан по прошлым сессиям — если конфиг уже рабочий, просто убедись, что путь к Java 21 указан явно.

## Этап 3. Установка mcp-1c

### 3.1 Скачивание бинарника mcp-1c [В]

`github.com` во внутреннем контуре доступен по HTTP (подтверждено твоей диагностикой), но releases на GitHub могут идти через поддомены, которые не проверялись отдельно — надёжнее скачать через внешний контур или дом. Браузер — только ты, агент туда доступа не имеет.

Открой `https://github.com/feenlace/mcp-1c/releases/latest`, скачай архив под Windows amd64 (обычно вида `mcp-1c_windows_amd64.zip` — точное имя смотри в списке Assets на странице релиза). Распакуй, внутри — один `.exe`-файл размером 25-40 МБ.

> **Инфо:** Это статический бинарник на Go — не установщик, а готовая программа. Запускается без инсталляции, без зависимостей вроде Python или Node.js.

### 3.2 Перенос бинарника во внутренний контур [В]>[Р]>[А]

Файл заметно тяжелее текста, значит буфер обмена не подойдёт (или будет неудобен) — используем Яндекс Почту как единственный разрешённый внешний сервис для передачи файлов, как в твоём обычном воркфлоу.

[В] Отправь `.exe`-файл вложением на свой Яндекс-адрес, доступный из обоих контуров.
[Р] Забери вложение на ПК внутреннего контура через почтовый веб-интерфейс, сохрани в любую временную папку, например `C:\Temp\`.
[А] Дай агенту задачу переложить файл в целевой путь `C:\Projects\!OTHER\mcp-1c\mcp-1c.exe`.

## Этап 4. Публикация HTTP-сервиса и установка расширения 1С

### 4.1 Автоустановка расширения в базу [А]

`mcp-1c` сам умеет находить платформу, ставить в базу служебное расширение и обновлять конфигурацию БД — одна команда вместо ручной сборки `.cfe` и загрузки через Конфигуратор. Попроси агента выполнить:

```powershell
& "C:\Projects\!OTHER\mcp-1c\mcp-1c.exe" --install "C:\путь\к\твоей\базе"
```

Сообщи агенту версию платформы из шага 1.1 — если она нестандартная и не определяется автоматически, агент должен добавить `--platform-version 8.3.XX` с реальным номером. Успех — сообщение об установке расширения и обновлении конфигурации базы. Перед запуском убедись сам, что база не открыта в Конфигураторе или толстом клиенте (обновление идёт через `DESIGNER`, требует эксклюзивного доступа) — это тебе нужно проверить и закрыть, агент это не увидит.

> Не проверено на твоей машине — по документации `mcp-1c`. Если команда завершится ошибкой доступа — вероятно, база открыта где-то ещё, закрой все сессии и повтори.

### 4.2 Публикация HTTP-сервиса на веб-сервере [Р]

Расширение, поставленное на шаге 4.1, содержит HTTP-сервис — но чтобы `mcp-1c` мог к нему достучаться постоянно (не только в момент установки), сервис нужно опубликовать на веб-сервере, как ты подтвердил — возможность есть. Пункт меню Конфигуратора, не команда — только ты.

В Конфигураторе: `Администрирование > Публикация на веб-сервере...`. Укажи имя публикации (например `mcp1c`), выбери Apache или IIS (какой у тебя настроен), отметь публикацию расширения `MCP_HTTPService`. Успех — Конфигуратор сообщает о создании файла публикации без ошибок.

> **Инфо:** Публикация на веб-сервере — штатный механизм 1С для доступа к базе по HTTP/HTTPS (то же самое, что используется для веб-клиента или обмена данными). Расширение просто добавляет туда ещё один сервис, специфичный для `mcp-1c`.

### 4.3 Проверка HTTP-сервиса [А]

Убеждаемся, что сервис действительно отвечает, прежде чем настраивать сам Zoo Code — если тут ошибка, искать её проще сейчас, чем после подключения MCP. Попроси агента выполнить:

```powershell
curl http://localhost/mcp1c/hs/mcp-1c/version
```

(замени `mcp1c` на реальное имя публикации из шага 4.2). Успех — в ответе версия сервиса в виде текста/JSON. Ошибка соединения — веб-сервер не видит публикацию (перепроверь шаг 4.2 сам — это снова GUI); `404` — неверный путь в URL (агент может проверить имя публикации и что расширение реально подключено, сверившись с шагом 4.2).

## Этап 5. Подключение MCP к Zoo Code

### 5.1 Добавление mcp-1c в `.roo/mcp.json` [А]

Формат конфигурации одинаков для любого MCP-клиента — просто добавляем ещё один сервер рядом с уже настроенным BSL Language Server (если он там уже прописан как MCP, а не как отдельное расширение). Попроси агента добавить в `C:\Projects\1C_ERP\.roo\mcp.json`:

```json
{
  "mcpServers": {
    "1c": {
      "command": "C:\\Projects\\!OTHER\\mcp-1c\\mcp-1c.exe",
      "args": ["--base", "http://localhost/mcp1c/hs/mcp-1c"]
    }
  }
}
```

Если в файле уже есть другие MCP-серверы — агент должен вписать блок `"1c": {...}` внутрь существующего `"mcpServers"`, не создавая второй `mcpServers`-ключ.

### 5.2 Перезапуск и проверка в Zoo Code [Р]

Финальная проверка всей цепочки — от VS Code до живой базы. Перезапуск окна и клик по иконке — твои действия в интерфейсе.

Перезапусти VS Code (или только окно Zoo Code через команду «Reload Window»). Открой панель Zoo Code, проверь список MCP-серверов (иконка сервера в верхней панели) — `1c` должен появиться в списке подключённых. В чате Zoo Code спроси: «Покажи структуру конфигурации моей базы 1С». Успех — агент вызывает инструмент `get_configuration_info` и возвращает реальное имя/версию твоей конфигурации, а не общий ответ по памяти.

## Этап 6. Правила разработки 1С для агента

Не все файлы правил в `ai_rules_1c` самодостаточны — часть содержит только заголовки разделов, а сам текст стандарта лежит в отдельной базе, которая раздаётся исключительно через MCP-сервер `1c-code-check-mcp` (Docker, вне рамок этого минимального плана). Переносить стоит только файлы с полным текстом — иначе получишь пустой скелет вместо правила.

Полнотекстовые (по состоянию на момент подготовки плана — список может измениться в репозитории со временем, стоит свериться на месте): `module-structure.md`, `dev-standards-env.md`, `dev-standards-change-markers.md`, `forms.md`, `form-patterns.md`, `forms-add.md`, `form-module.md`, `async-methods.md`, `extension-patterns.md`, `dcs-design.md`, `registers-design.md`, `query-design.md`, `metadata-xml-workarounds.md`, `logging-strategy.md`, `project-memory.md`.

Только заголовки, без полезного текста без MCP (пропустить): `anti-patterns.md`, `dev-standards-architecture.md`, `dev-standards-code-style.md`, `platform-solutions.md`, `locks-and-transactions.md`, `systematic-debugging.md`, и другие из этой группы — полный список см. в README репозитория, раздел «Куда уехали детальные стандарты».

### 6.1 Скачивание отобранных файлов [В]

`github.com` во внутреннем контуре доступен только частично (см. твою диагностику) — надёжнее забрать файлы через внешний контур/дом, как и бинарник `mcp-1c`. Браузер — только ты.

Открой в браузере `https://github.com/comol/ai_rules_1c/tree/main/content/rules`, скачай (кнопка «Raw» > «Сохранить как») файлы из полнотекстового списка выше, которые актуальны для твоих задач — не обязательно все сразу, можно начать с `module-structure.md` (шаблоны регионов кода — самое непосредственно применимое к повседневной правке модулей).

> **Инфо:** «Raw» показывает файл как чистый текст без обвязки интерфейса GitHub — то, что нужно сохранить, а не HTML-страницу с разметкой.

### 6.2 Перенос во внутренний контур [В]>[Р]>[А]

Это текстовые `.md`-файлы, небольшие по размеру — подходят и под буфер обмена, и под почту, в отличие от бинарника `mcp-1c.exe`.

[В] Отправь файлы вложением на свой Яндекс-адрес.
[Р] Забери вложения на ПК внутреннего контура, сохрани во временную папку, например `C:\Temp\rules\`.
[А] Дай агенту задачу переложить файлы в `C:\Projects\1C_ERP\.roo\rules-code\`, сохранив исходные имена (например `module-structure.md`).

### 6.3 Проверка подключения правил [Р]

Roo/Zoo Code подхватывает всё содержимое `.roo/rules-code/*.md` автоматически при сборке системного промпта для мода Code — отдельного шага включения не требуется, но стоит убедиться, что агент их реально видит. Вопрос в чате — твоё действие.

В чате Zoo Code спроси: «Какие правила именования регионов в общих модулях BSL ты знаешь?» (если перенёс `module-structure.md`). Успех — агент отвечает конкретными названиями регионов из файла (например `#Область ПрограммныйИнтерфейс`), а не общими рассуждениями о структуре кода.

> Не проверено на твоей машине — по документации Roo Code (структура Custom Instructions, раздел Rules). Если агент не видит правила — проверь, что путь именно `.roo/rules-code/` (не `.roorules-code` устаревшего формата) и что файлы лежат в корне проекта, который открыт в VS Code.

## Этап 7. Дополнительные MCP: точность кода и экономия токенов

Два сервера сверх `mcp-1c`, отобранные по сравнению из 10 актуальных проектов экосистемы (см. `mcp-1c-comparison.md`). Оба помечены ?? Beta в каталоге `Untru/1c-mcp` — API может измениться без предупреждения. Осознанно не берём `1c-mcp-toolkit` (альтернативный способ публикации без веб-сервера) — штатная публикация через Apache/IIS (Этап 4) надёжнее, если план когда-то пойдёт дальше тебя одного.

### 7.1 mcp-bsl-lsp-bridge — точность кода через тот же BSL LS [В]>[Р]>[А]

Мост LSP>MCP: даёт агенту то, что уже видит BSL Language Server (Этап 2) — навигацию по коду, поиск символов, диагностику (100+ проверок), hover-подсказки — но через MCP, а не только подсветкой в редакторе. Не новый индекс, а второй канал к уже настроенному инструменту — минимальная дополнительная инфраструктурная стоимость.

[В] Скачай бинарник/исходник с `https://github.com/SteelMorgan/mcp-bsl-lsp-bridge` (README репозитория уточнит точный способ — beta-статус, установка может измениться с момента подготовки этого плана).
[Р] Перенеси через Яндекс Почту, как в Этапе 3.
[А] Дай агенту задачу: распаковать/разместить, прописать в `.roo/mcp.json` как отдельный сервер `bsl-lsp`, указав путь к уже установленному `bsl-language-server-1.0.7.jar` (тот же путь, что в Этапе 2.4).

> Не проверено на месте — сервер в статусе Beta, точный формат конфигурации мог измениться. Если подключение не заработает с первого раза — попроси агента свериться с актуальным README репозитория напрямую.

### 7.2 rlm-tools-bsl — экономия токенов на больших конфигурациях [В]>[Р]>[А]

Токен-эффективный анализ BSL без обязательного RAG (без Qdrant/Docker) — 6 MCP-инструментов и песочница с 62 хелперами, SQLite-индекс методов и графа вызовов, `git_search` через `git grep` для кода в git-репозитории. Прямое попадание в задачу "меньше токенов" на больших конфигурациях (ERP, УХ) — не альтернатива `mcp-1c`, а более экономный способ анализа именно кода, когда конфигурация большая.

Требует Python 3.10+ — проверь, что он есть во внутреннем контуре (в overview проекта установлен git/VS Code/Node.js, Python отдельно не упомянут).

[В] Скачай/собери проект с `https://github.com/Dach-Coin/rlm-tools-bsl` — репозиторий предпочитает PyPI или `uv` для установки, но в изолированном контуре без интернета уместнее скачать zip исходников целиком.
[Р] Перенеси во внутренний контур обычным путём (почта — если небольшой архив, иначе может понадобиться несколько вложений).
[А] Дай агенту задачу: установить зависимости (`pip install` из локально перенесённых пакетов, если PyPI недоступен напрямую — уточни у агента, какие пакеты нужны, и перенеси их тем же способом), настроить `.roo/mcp.json` вторым сервером `rlm-bsl` с транспортом Streamable HTTP (рекомендуемый) или stdio.

> Не проверено на месте — самый сложный шаг по установке из всех в этом плане (Python-зависимости в изолированной сети). Если офлайн-установка пакетов окажется практически неудобной — это сигнал отложить 7.2 до появления доступа к внутреннему PyPI-зеркалу или до момента, когда можно тестировать через внешний контур/дом.

### 7.3 Проверка обоих серверов [Р]

В чате Zoo Code после перезапуска (как в 5.2) проверь список подключённых MCP-серверов — должны появиться `1c`, `bsl-lsp`, `rlm-bsl` (если оба этапа пройдены). Задай агенту вопрос, требующий диагностики конкретного модуля («какие ошибки видит BSL LS в этом файле») — успех, если ответ явно ссылается на диагностику, а не на общие рассуждения о коде.

## Что это даёт и чего не делает

По завершении: ты редактируешь код текстом в VS Code (выгрузка + BSL LS), Zoo Code читает и правит те же файлы по твоей команде, опираясь на перенесённые правила разработки, и через `mcp-1c` может спросить у живой базы структуру объектов, формы, выполнить SELECT-запрос, поискать и прочитать код по имени объекта — не тратя токены на пересказ структуры текстом. `mcp-bsl-lsp-bridge` добавляет точность за счёт диагностики BSL LS через MCP; `rlm-tools-bsl` — дополнительную экономию токенов на больших конфигурациях за счёт индекса методов и графа вызовов без RAG.

Не входит в этот минимум: автоматизация выгрузки/загрузки/обновления конфигурации (остаётся ручной операцией в Конфигураторе, как на шаге 1.2), операции записи в базу через `mcp-1c` (read-only), полный набор правил `ai_rules_1c` (часть файлов без Docker остаются пустыми заголовками), субагенты и слэш-команды `ai_rules_1c` (заточены под Claude Code/Cursor/Codex — не под Roo/Zoo Code), сами MCP-серверы экосистемы `ai_rules_1c` и `mcp-1c-v1` (Docker, за рамками этого плана), альтернативный способ публикации `1c-mcp-toolkit` (сознательно не взят — см. Этап 7 выше).
